# Orb Blast 3D

A Unity WebGL build served from GitHub Pages as part of
[Little Joy Arcade](https://littlejoyarcade.site).

- **Play:** <https://jd4rider.github.io/orb-blast-3d-web/play/>
- **Cover page:** <https://jd4rider.github.io/orb-blast-3d-web/>

## What is in here

```text
build/WebGL/                the untouched Unity WebGL export (uncompressed)
scripts/prepare-site.mjs    turns the export into a Pages-servable site
site/                       generated by the script, not committed
.github/workflows/pages.yml prepare + deploy on every push to main
arcade-manifest.json        the catalogue entry for littlejoyarcade.site
```

There is no bundler, no framework and no dependencies. The only build step is
`node scripts/prepare-site.mjs`, which needs nothing but Node.

The Unity project lives separately, at `~/Developer/Orb Blast 3D`. Its editor script
`Assets/OrbBlast3D/Editor/WebGLBuildSetup.cs` writes the export straight to
`Builds/WebGL`; copy that folder here.

## Why there is a build step at all

**Compression.** Unity's default export Brotli-compresses the payload and expects the
server to answer with `Content-Encoding: br`. Pages serves files verbatim and lets you
set no response headers, so the browser would hand raw Brotli bytes to the loader and
the game would stop at the progress bar. The build script therefore exports with
compression **disabled** (`PlayerSettings.WebGL.compressionFormat = Disabled`). The
script still expands any `.br` payload it finds, so a future export that turns Brotli
back on still deploys.

**Layout.** The stock Unity template pins a fixed 960x600 play area and stretches the
canvas on phones. Orb Blast 3D frames its own board to whatever canvas it is given
(`CameraController` reserves the top and bottom HUD bands and fits the board between
them), so the canvas is made to fill the window instead.

**Caching.** Unity keeps the payload in IndexedDB keyed by the data URL and
`productVersion`, so an unversioned export replays whatever build a player first loaded.
`prepare-site.mjs` hashes the payload into both the loader URLs and `productVersion`:
repeat visits stay cached, a real change always lands.

## Local check

```bash
node scripts/prepare-site.mjs
python3 -m http.server 8000 --directory site   # http://127.0.0.1:8000/play/
```

## Limits worth knowing

- This is the gameplay-foundation build: 5 hand-authored levels, no progression save,
  no audio and no Little Joy Arcade account layer yet. `saveKey` is empty on purpose.
- The aim guide draws every rail bounce at full strength, so a shallow aim paints a
  staircase across the whole board. It is truthful - the flight uses the same plan.
- There is no reflection probe or environment map, so the spheres read as lit coloured
  discs rather than glossy glass.
